# 3D Argument Graph — Implementation Plan

An optional spatial explorer at `/graph/3d` powered by `3d-force-graph`. The 2D graph at `/graph` stays the default; `/graph/3d` is an alternative view of the same data.

---

## Guiding constraints

- **No new SQL or backend queries.** The existing `/graph/data` JSON endpoint (same `{nodes, edges}` shape) feeds both views.
- **Same filter set.** Author, group, tag, since, sourced, visibility, node type, edge kind, and depth all work the same way.
- **Vendor the library.** Follow the same pattern as `htmx.min.js` and `easymde.min.js` — no CDN fetches at runtime.
- **Reuse 2D constants.** `KIND_LINK` distances/strengths and node radius values carry over directly from `app.js`.

## Backend

### New handler (`handlers_graph.go`)

Add `handleArgumentGraph3D` immediately after `handleArgumentGraphData` (~line 130).
It is nearly identical to `handleArgumentGraph` — the only difference is the template it renders:

```go
func (s *Server) handleArgumentGraph3D(w http.ResponseWriter, r *http.Request) {
    filters := parseGraphFilters(r)
    data, err := s.loadArgumentGraph(r.Context(), currentUser(r), filters)
    if err != nil {
        s.logger.Error("argument graph 3d: load", "err", err)
        renderError(w, r, http.StatusInternalServerError)
        return
    }
    render(w, r, views.ArgumentGraph3D(viewerFor(currentUser(r)), data, graphFiltersForView(filters)))
}
```

### Route registration (`server.go`, near line 228)

```go
r.Get("/graph/3d", s.handleArgumentGraph3D)
```

Place it between `GET /graph/data` and `GET /graph/nodes/suggest`.

```

  └── site layout head
      └── <div data-argument-graph-3d
               data-argument-graph-endpoint="/graph/data">
            <script type="application/json"
                    data-argument-graph-data>   ← same inline JSON trick as graph.templ
              { nodes: [...], edges: [...] }
            </script>
            <script type="application/json"
                    data-argument-graph-filters>
              { q: "...", author: "...", ... }
            </script>
            ┌── toolbar row
            │     2D view link  |  3D view (active)  |  shuffle  |  zoom
            ├── filter sidebar  ← copy from graph.templ (same data-* attrs)
            ├── #graph3d-container  ← 3d-force-graph mounts here (height: 72vh)
            └── inspector panel ← copy from graph.templ (same data-graph-title etc.)
  └── <script src="/static/3d-force-graph.min.js">
  └── <script src="/static/graph3d.js">
```

**Key data attributes** — all reuse the same names as `graph.templ` so the filter wiring, HTMX suggests, and inspector JS need no changes:


The "2D view" link: `<a href="/graph?{current query params}">2D</a>`  
The "3D view" link: `<a href="/graph/3d?{current query params}" aria-current="page">3D</a>`

Mirror the same links in `graph.templ` so both pages toggle to each other.

## Frontend (`static/graph3d.js`)

Everything in one closure `initArgumentGraph3D(el)`, called on every `[data-argument-graph-3d]` element. No globals.

### Visual constants

```js
const NODE_COLOR  = { topic: '#7c6fd4', view: '#5a9fd4', finding: '#4dab8a', comment: '#8b8b8b' };
const NODE_RADIUS = { topic: 10, view: 8, finding: 7, comment: 5 };  // nodeVal = radius²

const EDGE_COLOR  = {
  supports: '#4dab8a', opposes: '#d45a5a', refines: '#d4a85a',
  cites: '#5a8fd4',    related: '#8b8b8b', comments_on: '#8b8b8b',
};

// Same tuning as app.js KIND_LINK
const KIND_LINK = {
  supports:    { distance: 200, strength: 0.28 },
  opposes:     { distance: 255, strength: 0.25 },
  refines:     { distance: 160, strength: 0.50 },
  cites:       { distance: 195, strength: 0.40 },
  related:     { distance: 230, strength: 0.28 },
  comments_on: { distance: 155, strength: 0.45 },
};

// Z-axis type gravity (mirrors 2D x-column bias: topic → left, finding → right)
const TYPE_Z = { topic: -280, view: 0, finding: 280 };
const TYPE_Z_STRENGTH = 0.006;  // same weak bias as 2D type gravity
```

### Data normalisation

Same `normalizeGraphData(next)` logic as `app.js`:
- Build `nodesByID` map.
- Drop edges whose endpoints are missing.
- Rename `relates_to` → `related` for display consistency.
- Build `adjacency` map for O(1) neighbour lookup (used for dimming).

### Filter pipeline

Same `filteredNodes()` / `filteredEdges()` as `app.js`:
- Client-side: type checkboxes, BFS from seeds up to `currentDepth()` hops.
- Server-side: `fetchServerGraph()` debounced 220 ms when author/group/tag/since/sourced/visibility change.

When `filteredNodes()` returns a new set, call `Graph.graphData({ nodes: filtered, links: filteredEdges() })`. The library re-runs its simulation automatically.

### 3d-force-graph initialisation

```js
const container = el.querySelector('#graph3d-container');

const Graph = ForceGraph3D()(container)
  .backgroundColor('#0d0d14')
  .nodeId('id')
  .nodeLabel('title')
  .nodeColor(n => nodeColor(n))
  .nodeVal(n => NODE_RADIUS[n.type] ** 2 ?? 25)
  .linkSource('from_id')
  .linkTarget('to_id')
  .linkColor(e => EDGE_COLOR[e.kind] ?? '#888')
  .linkWidth(1.5)
  .linkOpacity(0.6)
  .linkDirectionalArrowLength(8)
  .linkDirectionalArrowRelPos(1)
  .onNodeClick(handleNodeClick)
  .onBackgroundClick(() => clearSelection());
```

### Force configuration (after `ForceGraph3D()` call)

```js
// Override link distances/strengths with KIND_LINK values
Graph.d3Force('link')
  .distance(link => KIND_LINK[link.kind]?.distance ?? 200)
  .strength(link => KIND_LINK[link.kind]?.strength ?? 0.28);

// Charge (repulsion)
Graph.d3Force('charge').strength(-300);

// Z-axis type gravity (3D extension of 2D column bias)
// d3-force-3d exposes forceZ; import it from the bundle's d3 namespace
Graph.d3Force('typeZ',
  d3.forceZ(n => TYPE_Z[n.type] ?? 0).strength(TYPE_Z_STRENGTH)
);
```

### Dimming on selection

`nodeColor(n)` reads `selectedID`. When a node is selected, nodes not adjacent to it get opacity lowered by multiplying their color toward the background:

```js
function nodeColor(n) {
  const base = NODE_COLOR[n.type] ?? '#888';
  if (!selectedID) return base;
  if (n.id === selectedID || adjacency[selectedID]?.[n.id]) return base;
  return dimHex(base, 0.18);  // mix toward #0d0d14, keep 18% of original
}
```

After selection changes, call `Graph.nodeColor(nodeColor)` to trigger a repaint without resimulating.

### Zoom controls

The "in / out / reset" buttons (`data-graph-zoom`) call:

```js
// zoom in
Graph.camera().position.multiplyScalar(0.8);
Graph.renderer().render(Graph.scene(), Graph.camera());

// zoom out
Graph.camera().position.multiplyScalar(1.25);

// reset
Graph.zoomToFit(400);  // 400 ms animation
```

### Reshuffle

```js
Graph.d3ReheatSimulation();
```

### Inspector panel

`handleNodeClick(node)` fills the same `data-graph-title`, `data-graph-meta`, `data-graph-open`, and `data-graph-author-pin` elements as the 2D inspector. No new code — the inspector HTML and CSS are unchanged.

### Visible count

After every `graphData` update, read `Graph.graphData().nodes.length` and write it to `data-graph-visible-count`.

---

## Visual identity

The 3D view is deliberately dark (`backgroundColor: '#0d0d14'`) to visually distinguish it from the 2D graph's white SVG canvas. Everything else (colors, filter sidebar layout, inspector) is identical.

Node labels are shown as floating sprites via `nodeLabel`. Hovering a node triggers the built-in tooltip (`nodeLabel`); clicking opens the inspector panel.

## Vendor bundle

Download `3d-force-graph.min.js` from the project's npm release (UMD build):

```
https://unpkg.com/3d-force-graph/dist/3d-force-graph.min.js
```

Current stable version: **1.73.x**.  
Place at `static/3d-force-graph.min.js`. Size: ~1.3 MB minified (~320 KB gzip).  
The bundle exposes `ForceGraph3D` as a global and includes Three.js r150 and d3-force-3d.

This file is only loaded on `/graph/3d`. The 2D graph page is unaffected.

## Out of scope (for this phase)

- **Performance above the existing caps.** The 120-node / 320-edge limits already in `handlers_graph.go` apply unchanged. WebGL handles this count trivially.
- **VR / AR mode.** `3d-force-graph` supports it via WebXR but it is not planned.
- **Shared filter partial.** The filter sidebar HTML is duplicated between `graph.templ` and `graph3d.templ` for simplicity. Extracting it to a shared component is a follow-up.
- **Persist 3D camera state.** Camera orientation resets on page refresh (same as 2D pan/zoom).
